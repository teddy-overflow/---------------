# NuGet Dependency Graph Visualizer

## Описание проекта

Проект представляет собой инструмент для построения и анализа графа зависимостей пакетов NuGet.

Программа загружает настройки из XML-файла, самостоятельно скачивает NuGet-пакеты, извлекает информацию об их зависимостях и строит граф зависимостей.

Для обхода графа используется итеративный алгоритм поиска в глубину (DFS) без рекурсии.

Также программа определяет порядок установки пакетов с помощью топологической сортировки. Зависимости выводятся раньше пакетов, которые от них зависят.

## Параметры конфигурации

Настройки задаются в файле `config.xml`.

| Параметр       | Описание                                        |
| -------------- | ----------------------------------------------- |
| `package_name` | Имя анализируемого пакета                       |
| `repository`   | URL репозитория или путь к тестовому JSON-файлу |
| `test_mode`    | Включение тестового режима                      |
| `version`      | Версия анализируемого пакета                    |
| `output_file`  | Имя выходного SVG-файла                         |
| `ascii_tree`   | Включение древовидного вывода в консоль         |
| `max_depth`    | Максимальная глубина анализа зависимостей       |

## Основные функции

### Модуль `config.py`

- `get_value()` — получает обязательное значение из XML.
- `validate_boolean()` — проверяет логические параметры.
- `validate_repository()` — проверяет URL или путь к тестовому файлу.
- `validate_output_file()` — проверяет имя и расширение выходного файла.
- `validate_max_depth()` — проверяет глубину анализа.
- `load_config()` — загружает и проверяет конфигурацию.

### Модуль `nuget.py`

- `build_package_url()` — формирует URL NuGet-пакета.
- `download_package()` — скачивает пакет из репозитория.
- `extract_nuspec()` — извлекает файл `.nuspec` из архива `.nupkg`.
- `parse_dependencies()` — извлекает зависимости из XML.
- `fetch_direct_dependencies()` — получает прямые зависимости пакета.

### Модуль `graph.py`

- `load_test_graph()` — загружает тестовый граф из JSON-файла и проверяет его структуру.
- `create_node_id()` — создаёт уникальный идентификатор узла по имени и версии пакета.
- `build_dependency_graph()` — строит граф зависимостей с помощью итеративного DFS.
- `get_installation_order()` — определяет порядок установки пакетов с помощью топологической сортировки.
- Использует стек вместо рекурсии.
- Ограничивает обход параметром `max_depth`.
- Предотвращает бесконечный обход циклических зависимостей.
- Проверяет наличие всех узлов, необходимых для определения порядка установки.

### Модуль `main.py`

Запускает программу, загружает конфигурацию, строит граф зависимостей, выводит его в консоль в виде дерева или списка связей и показывает порядок установки пакетов.

## Алгоритм определения порядка установки

Для определения порядка установки используется итеративный обход графа в глубину.

Алгоритм обрабатывает зависимости каждого пакета до добавления самого пакета в итоговый список.

Таким образом, зависимые пакеты оказываются в списке после своих зависимостей.

Для обнаружения циклов используются три состояния узлов:

- `0` — узел ещё не посещён;
- `1` — узел находится в процессе обработки;
- `2` — обработка узла завершена.

Если во время обхода обнаруживается цикл, программа сообщает об ошибке.

Каждый узел добавляется в итоговый порядок только один раз. Это позволяет корректно обрабатывать графы с общими зависимостями.

## Режимы работы

### Обычный режим

При `test_mode=false` программа получает данные из NuGet-репозитория.

Пример настроек:

```xml
<repository>
    https://api.nuget.org/v3-flatcontainer/
</repository>
<test_mode>false</test_mode>
```

### Тестовый режим

При `test_mode=true` программа использует JSON-файл с заранее подготовленным графом зависимостей.

Пример настроек:

```xml
<repository>tests/test_graph.json</repository>
<test_mode>true</test_mode>
```

Названия пакетов в тестовом JSON должны состоять из заглавных латинских букв, цифр, точек, дефисов или подчёркиваний.

Тестовый режим позволяет проверять построение графа и определение порядка установки без обращения к интернету.

```

```

- обработку архивов `.nupkg`;
- извлечение и разбор XML-файлов `.nuspec`;
- получение прямых зависимостей;
- загрузку и проверку тестового графа;
- построение графа зависимостей;
- соблюдение максимальной глубины;
- защиту от циклических зависимостей;
- определение порядка установки пакетов;
- обработку циклов и отсутствующих узлов при топологической сортировке.

## Сравнение с менеджером пакетов NuGet

Для проверки результатов использовался настоящий менеджер пакетов NuGet через .NET SDK.

В качестве анализируемого пакета использовался `Newtonsoft.Json` версии `13.0.3`.

Для целевой платформы `netstandard1.3` были получены следующие прямые зависимости:

- `Microsoft.CSharp` — `4.3.0`;
- `NETStandard.Library` — `1.6.1`;
- `System.ComponentModel.TypeConverter` — `4.3.0`;
- `System.Runtime.Serialization.Formatters` — `4.3.0`;
- `System.Runtime.Serialization.Primitives` — `4.3.0`;
- `System.Xml.XmlDocument` — `4.3.0`.

Результат собственного парсера `.nuspec` полностью совпал с результатом NuGet: все 6 прямых зависимостей и их версии совпали.

При этом NuGet дополнительно разрешает транзитивные зависимости и учитывает целевую платформу проекта. Например, для `net10.0` у `Newtonsoft.Json` была выбрана другая группа зависимостей, не содержащая внешних пакетов.

Таким образом, результаты могут отличаться в зависимости от целевой платформы и глубины анализа.

NuGet формирует граф разрешённых зависимостей, но не задаёт единственную обязательную линейную последовательность физической установки пакетов. Поэтому в проекте проверяется корректность собственного порядка установки: зависимости должны располагаться раньше пакетов, которые от них зависят.
